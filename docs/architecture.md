# Architecture

PaaniPulse is a static single-page application. Everything runs in the browser; the only network dependencies are free, keyless public services.

```
GitHub Pages (static files: app bundle, gazetteer chunk)
        │
        ▼
Browser ── React UI ── MapLibre GL JS ──► OpenFreeMap vector tiles (OSM data)
   │
   ├─ place search ──► bundled gazetteer → Photon (type-ahead) → Nominatim (on submit, ≤1 req/s)
   │
   ├─ lib/dem ──► Planetary Computer STAC search ──► SAS token ──► Azure Blob COG range reads
   │              (fallback, user-chosen) ──► AWS Terrain Tiles (Terrarium PNG)
   │
   ├─ lib/landcover ──► Planetary Computer ──► ESA WorldCover 2021 COG range reads
   │
   └─ workers/hydrology.worker ── lib/hydrology: Priority-Flood → D8 → accumulation → HAND → storage
                                  └─ per scenario: runoff → fill and spill → hotspot screening
```

## Hydrology worker

When terrain loads, `useHydrology` starts a module worker and sends it a copy of the elevations plus each row's cell width and height (transferred, not cloned). The worker reports each stage as it starts and returns the results as transferable typed arrays. It keeps the filled surface, directions and accumulation, so a new drainage threshold reruns HAND alone. A new selection or terrain load terminates the worker, which cancels any analysis in progress; replies carry a request id so a late message cannot overwrite newer results.

Rainfall scenarios are separate requests to the same worker. It reuses the stored routing, HAND and depressions, computes slope once per grid, and returns the active scenario's arrays plus summaries for the 50, 100 and 150 mm comparison. Run, threshold and scenario requests each have their own request counter, so a reply is only applied if it is the latest of its kind; a threshold change marks the current scenario as stale.

Algorithm outputs keep the grid's dimensions and row-major order, so every layer lines up with the elevation cells and their georeferencing. Missing-data cells stay missing in every output.

## 3D view

`Terrain3DView` is loaded with `React.lazy`, so Three.js stays out of the main bundle. MapLibre stays mounted underneath while it is open, so switching back keeps the map, selection and layers. The view creates one `TerrainScene` (renderer, orbit controls, lights, rain) for its lifetime and disposes every geometry, material, the shadow map and the WebGL context on close. Terrain is rebuilt when the grid or exaggeration changes; water when a scenario result arrives. Geometry comes from `src/lib/terrain3d/geometry.ts`, which reads but never writes the model arrays. Hotspot pins are sprites at the scoring cells of the same ranked hotspots the list shows; a click (a press that does not move) on one reports its rank to the app.

The app checks for WebGL before loading the chunk (`src/features/terrain3d/support.ts`). The view reports `onUnavailable` when WebGL is missing, the renderer cannot be created, or `webglcontextlost` fires; the app then shows the 2D map with a notice. Rendering errors inside the view are caught by an error boundary that offers the 2D map. Selection, scenario and hotspot state live in `App`, so no failure in the 3D view loses them.

## Elevation grid

An `ElevationGrid` is a north-up, row-major `Float32Array` with its outer cell edges, CRS and provenance. GLO-30 grids are in EPSG:4326 on the one-arc-second lattice; Terrarium grids are in Web Mercator at zoom 12. Cells with no data are `NaN`.

The terrain image colours each cell by elevation, stretched to the area's 2nd–98th percentile (with a minimum 2 m span so flat areas do not exaggerate noise), and multiplies it by a Horn hillshade computed from the same grid. It is drawn with nearest-neighbour resampling so individual DEM cells stay visible.

## Requests and failure handling

- A new terrain request aborts the previous one, and only the latest request may update the UI.
- Changing the selection discards the loaded terrain, so terrain is never shown for a different area.
- Catalogue, token and read failures surface as typed errors (`NO_COVERAGE`, `NETWORK`, `SIGNING`, `DECODE`) with a retry. The coarser fallback is offered but never chosen automatically.
- The basemap is treated as unavailable if its style fails to load or does not load within 15 seconds; no substitute map is shown.
